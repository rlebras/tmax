# Terminal-eval runs — 2026-07-08 (reproduction commands)

Exact commands for the Vanillux2Agent terminal-bench eval sweep run on 2026-07-08.
All launched from the **`omni_agent`** branch of tmax at a HEAD that includes the
`--model-provider`, `--mirror-url`, and `--dataset-path` flags (commit `92c07afe`
or later). Re-running from current `omni_agent` HEAD reproduces everything.

## Prereqs

```bash
cd ~/code/tmax
git checkout omni_agent && git pull        # HEAD must be pushed (Gantry clones the SHA)
# Secrets in the workspace: HF_TOKEN, shashankg_DOCKER_PAT (defaults on this branch).
# Mirror (optional but recommended, avoids Docker Hub rate limits under co-location):
MIRROR=jupiter-cs-aus-137.reviz.ai2.in:5000
WS=ai2/oe-agents                            # default workspace going forward
# (NOTE: the 2026-07-08 runs below actually used ai2/general-tool-use; use ai2/oe-agents from now on.)
```

Common config for every run below: `--agent Vanillux2Agent:Vanillux2Agent`,
`--model-provider openai`, `--workspace $WS`, `--mirror-url $MIRROR`, dataset
terminal-bench 2.0 (89 tasks) unless noted.

Parser/flags by model family:
- **Qwen3.5** (Qwen3.5-*, tmax-2b/4b/9b/27b, Qwen3.6-27B): `--tool-call-parser qwen3_xml`
- **Qwen3** (Qwen3-8B, tmax-8b): `--tool-call-parser hermes --reasoning-parser qwen3`
- **`allenai/tmax-*`** (text-only fine-tunes, full config): add `--language-model-only`
- **RL `_cg` checkpoints / Qwen base / Reasoning-Fix**: no `--language-model-only`

## 1. Full TB2.0 fleet — k=8, 32k, Saturn

11 models. tmax-{2,4,9}b get `--language-model-only`; Qwen3-8B pair uses hermes+qwen3.

```bash
# Qwen3.5 family (qwen3_xml). tmax-* add --language-model-only:
for spec in \
  "Qwen/Qwen3.5-2B|qwen35-2b|0" "Qwen/Qwen3.5-4B|qwen35-4b|0" "Qwen/Qwen3.5-9B|qwen35-9b|0" \
  "allenai/tmax-2b|tmax-2b|1" "allenai/tmax-4b|tmax-4b|1" "allenai/tmax-9b|tmax-9b|1" \
  "shatu/Qwen3.5-2B-Reasoning-Fix|qwen35-2b-reasoning-fix|0" \
  "shatu/Qwen3.5-4B-Reasoning-Fix|qwen35-4b-reasoning-fix|0" \
  "shatu/Qwen3.5-9B-Reasoning-Fix|qwen35-9b-reasoning-fix|0"; do
  IFS='|' read -r MODEL NAME LM <<< "$spec"
  FLAGS=(--name "$NAME" --agent Vanillux2Agent:Vanillux2Agent --model-provider openai
         --tool-call-parser qwen3_xml --mirror-url "$MIRROR" --cluster ai2/saturn
         --gpus 1 --dataset terminal-bench@2.0 --max-model-len 32768 --n-attempts 8
         --job-name "${NAME}-vanillux2-tb2-k8" --workspace "$WS")
  [ "$LM" = 1 ] && FLAGS+=(--language-model-only)
  ./beaker_configs/launch_eval.sh "$MODEL" "${FLAGS[@]}"
done

# Qwen3-8B pair (hermes + reasoning-parser qwen3, no LM-only):
for spec in "allenai/tmax-8b|tmax-8b" "shatu/Qwen3-8B-Reasoning-Fix|qwen3-8b-reasoning-fix"; do
  IFS='|' read -r MODEL NAME <<< "$spec"
  ./beaker_configs/launch_eval.sh "$MODEL" --name "$NAME" \
    --agent Vanillux2Agent:Vanillux2Agent --model-provider openai \
    --tool-call-parser hermes --reasoning-parser qwen3 --mirror-url "$MIRROR" \
    --cluster ai2/saturn --gpus 1 --dataset terminal-bench@2.0 --max-model-len 32768 \
    --n-attempts 8 --job-name "${NAME}-vanillux2-tb2-k8" --workspace "$WS"
done
```

## Reproduction notes / gotchas

- **Push HEAD first** — Gantry clones the git SHA; an unpushed commit fails the clone
  (or pass `--repo-ref omni_agent`).
- **`--language-model-only` works for `allenai/tmax-*` (released, full config, missing
  only preprocessor file) but NOT for raw RL `step_N/` checkpoints** (`Qwen3_5TextConfig`,
  no vision_config → no vLLM arch registers it). Raw checkpoints must be CG-converted
  first (`dr-tulu:agent/scripts/convert_qwen35_causallm_to_cg.py --src <step> --donor Qwen/Qwen3.5-4B --out <..._cg>`).
- **Mirror**: same `alexgshaw/*` task images for 2.0 and 2.1; `--mirror-url` routes pulls
  through a docker.io pull-through cache; authenticated docker.io is the fallback.
- **exitCode 0 ≠ success** — check `result.json` → `stats.n_errored_trials`.
- **Gantry "Failed to resolve dataset `gantry-*-source-*`" / `BeakerDatasetConflict`**
  (all launches in a batch fail identically): the shared source-upload dataset got
  into a bad state. Fix: `beaker dataset delete shashankg/gantry-v3.7.0-source-<hash>`
  then relaunch — Gantry recreates it cleanly.
- **Results**: each job's beaker result dataset has `metrics.json` (pass@1/pass@N via
  compute_stats) + per-trial `agent/trajectory.json` + `verifier/reward.txt`. Fetch just
  the summary with `beaker dataset fetch <ds> --prefix metrics.json -o <dir>`.
